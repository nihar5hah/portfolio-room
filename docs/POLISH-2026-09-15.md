# Portfolio polish and verification — 15 September 2026

Completed in `/Users/niharshah/Misc/portfolio-remix`. The original portfolio was not edited. The room composition, personal content, black MacBook, album selections and existing camera choreography are preserved. No dependency, commit, push or deployment was added.

## Fixes

- **Quieter entry:** ambience is 25% lower throughout the camera range (0.0375–0.075 gain), and the startup cue changes from 0.4 to 0.3. Music rises slightly from 0.04 to 0.05. Native Web Audio gain is set before playback, eliminating the initial full-gain instant. These are gain settings, not perceived-loudness measurements.
- **Audio lifecycle:** positional effects use the sound's native scene node instead of allocating invisible debug spheres. Native object IDs avoid pool-key collisions when overlapping sounds finish out of order; ended sounds reset playback state, disconnect and leave the scene.
- **Slow library loading:** Enter enables sound even when the playlist is still loading. Arrival starts music unless the visitor has since muted it. Browser playback rejection remains visible and retryable.
- **Resizable portfolio:** the compact portfolio layout now follows its own window's width. It works in a narrow desktop window as well as on a phone. The shared resize handler clamps at its minimum dimensions instead of retaining its previous size when the pointer crosses the minimum.
- **Workspace menu:** the Apple button has an accessible name, exposes its controlled dropdown, and restores focus on Escape. Escape closes the menu before the room's camera keyboard handler can process it.
- **Cleanup and provenance:** removed the unused MusicPlayer and VideoAsset components and the retired barrel export (306 lines). Recoverable copies are under `.agent-artifacts/polish-2026-09-15/retired-components/`. Updated the README, audio guide and Credits to describe the current 114-track library and distinguish cover-derived labels from physical pressing photographs.

## Research informing the changes

The implementation uses the installed engine and browser features. Three.js describes positional audio as an Object3D that can be attached directly to the scene. [Three.js PositionalAudio](https://threejs.org/docs/pages/PositionalAudio.html)

A resizable app window is an appropriate CSS query container: its descendants respond to available container width rather than the whole browser viewport. [MDN container queries](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries)

Full tracks remain native media elements with gesture-based startup and visible controls; short effects retain Web Audio. [MDN Web Audio best practices](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices)

The review also considered target sizes and keyboard access. This is not a claim of complete WCAG conformance. [W3C target-size guidance](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)
