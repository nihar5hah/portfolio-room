## Direction

The site now reads as an invitation into Nihar’s room. Football, music, Begu, the bedroom and the working desk establish personality before the visitor reads the professional content. The Mac provides the familiar interface for that content. This is a coherent direction worth retaining.

The latest changes make the room less like a collection of large wall posters. Eleven small record sleeves now lean on shelves, the cabinet, console, bench, ledge and floor. The Barça flag remains the main wall feature. The TV and matching Messi frames form one composition, with bean bags and controllers providing an understandable reason to sit there. The separate record cabinet gives music an actual place in the room.

The visual hierarchy also makes sense: a dark room, warm wood and lamps, restrained blue/burgundy fabric, and a bright readable portfolio window. Dimming the room during Mac use reinforces that hierarchy. I would preserve this composition and fix the interaction and access problems below before adding more objects or effects.

## Findings, in priority order

### 1. P1 — One failed decorative asset blocks access to the portfolio

**Location:** [LoadingScreen.tsx:69](/Users/niharshah/Misc/portfolio-remix/src/Application/UI/components/LoadingScreen.tsx:69), with the shared resource gate in [Resources.ts:75](/Users/niharshah/Misc/portfolio-remix/src/Application/Utils/Resources.ts:75).

I blocked only `/room/fouryou-vinyl.jpg` in the browser and reloaded. Loading stopped at 98%, the only button became disabled “Room unavailable,” and the outer page had zero links. The portfolio content itself was not the failed resource.

Every resource, including all 38 album-art textures, is required before `World` initializes. The new login displays the error but provides neither retry nor access to `/desktop/`. The synchronous WebGL exception fallback in `src/script.ts` does not catch this asynchronous asset failure.

**Smallest useful correction:** always provide a direct portfolio link on the loading/error screen. Separately, let optional album art fall back without blocking the room. Do not merely enable Enter while `World` is uninitialized.

Evidence: [asset-failure.png](/Users/niharshah/Misc/portfolio-remix/.agent-artifacts/review-2026-09-15/asset-failure.png).

### 2. P1 — The main phone journey makes the portfolio too small to read

**Location:** [MonitorScreen.ts:202](/Users/niharshah/Misc/portfolio-remix/src/Application/World/MonitorScreen.ts:202), using the fixed display dimensions in [Computer.ts:4](/Users/niharshah/Misc/portfolio-remix/src/Application/World/Computer.ts:4).

At a verified 390 × 844 viewport, after “Use the Mac” settled, the iframe was still a 1512-pixel-wide desktop. Its projected bounds were approximately 438 × 271 pixels, extending 24 pixels beyond each side of the viewport. The 15-pixel desktop body text is therefore roughly 4.3 pixels tall on the page. The sidebar and application controls shrink with it, and the inner mobile breakpoints never activate.

There is no visible direct-desktop link in the outer room UI. `/desktop/` already renders much more readable content at this width, so there is an existing solution to reuse.

**Correction:** preserve the room introduction on phones, then provide an obvious route to a full-size responsive desktop/content view when the visitor wants to read. This does not require replacing the desktop camera animation.

Evidence: [mobile-room.png](/Users/niharshah/Misc/portfolio-remix/.agent-artifacts/review-2026-09-15/mobile-room.png).

### 3. P2 — A window can keep dragging after release outside the laptop

**Location:** [Window.tsx:113](/Users/niharshah/Misc/portfolio-remix/desktop/src/components/os/Window.tsx:113). The resize handlers at line 90 use the same event ownership pattern.

Reproduction: open Music inside the Mac; press its title bar; drag outside the physical screen; release; move back onto the screen without pressing again. Native browser mouse input reproduced the problem: Music ended the outward drag at `left:607px; top:202px`, then jumped to `left:43px; top:272px` on pointer re-entry with no button held.

The child window installs `mousemove`/`mouseup` listeners inside the iframe. Release in the parent reaches the room’s camera logic, but does not end the child’s gesture. Writing geometry directly to the DOM improves drag responsiveness; it does not solve ownership of the pointer across the iframe boundary.

**Correction:** make the shared Window gesture end reliably across that boundary, for example with native pointer capture and cancellation handling. Cover drag and resize together. Extend the existing navigation check with a real iframe/window release case; its current simulated events check camera transitions only.

Evidence: [drag-release.json](/Users/niharshah/Misc/portfolio-remix/.agent-artifacts/review-2026-09-15/drag-release.json).

### 4. P2 — Look around leaves the room in its dimmed Mac state

**Location:** [Renderer.ts:112](/Users/niharshah/Misc/portfolio-remix/src/Application/Renderer.ts:112), called through [InterfaceUI.tsx:115](/Users/niharshah/Misc/portfolio-remix/src/Application/UI/components/InterfaceUI.tsx:115).

Reproduction: Use the Mac → Look around. The controls correctly change to “Reset camera” and “Use the Mac,” `inside` becomes false and free camera activates, but both target and actual exposure remain 0.42 instead of the room’s normal 0.85. Waiting for the transition to finish did not restore it.

The renderer restores brightness only on `leftMonitor`; the free-camera path never emits that event. This makes the furnishings unnecessarily dark precisely when someone explores them.

**Correction:** restore room exposure whenever the camera leaves the monitor state, including free-camera entry and reset. Keep this consistent in the shared state/transition flow rather than patching individual visual objects.

Evidence: [look-around-exposure.json](/Users/niharshah/Misc/portfolio-remix/.agent-artifacts/review-2026-09-15/look-around-exposure.json).

### 5. P2 — Music never finishes loading in the standalone desktop

**Location:** [Music.tsx:47](/Users/niharshah/Misc/portfolio-remix/desktop/src/components/applications/Music.tsx:47).

Open `/desktop/` directly and launch Music. It stays on “Loading library…” indefinitely. `window.parent` is the window itself there, and no room-owned `AlbumAudio` exists to answer the state request. The same permanent loading state can occur if the room’s manifest fails to load.

**Correction:** handle the missing-player state explicitly. The minimum is a truthful room-only explanation/link or hiding the unavailable app in the standalone desktop. If standalone playback is desired, reuse the existing player rather than building a second audio system. Failed manifest loading also needs a terminal unavailable state.

Evidence: [standalone-music.png](/Users/niharshah/Misc/portfolio-remix/.agent-artifacts/review-2026-09-15/standalone-music.png).

### 6. P2 — The appended desktop skin overrides mobile and accessibility rules

**Location:** [index.css:2129](/Users/niharshah/Misc/portfolio-remix/desktop/src/index.css:2129), and the window buttons at [index.css:2044](/Users/niharshah/Misc/portfolio-remix/desktop/src/index.css:2044).

The earlier mobile rules make navigation labels 9px and window buttons 24px. Later unconditional rules restore 13px navigation labels and 12px buttons. At 390px, About/Experience/Notes crowd together visibly; the top menu also extends beyond the viewport. The new `.portfolio-nav` width/padding and `.portfolio-page` padding likewise override their earlier mobile values. The reduced-transparency rule appears before the new blur/background declarations and can also be overridden.

**Correction:** consolidate the active desktop styles, then put the intended narrow-screen and preference overrides after them. This is a cascade problem, not a reason to introduce another styling dependency.

Evidence: [mobile-desktop.png](/Users/niharshah/Misc/portfolio-remix/.agent-artifacts/review-2026-09-15/mobile-desktop.png).

## What I would refine after the fixes

- Keep the smaller sleeves and existing furniture layout. More large posters or more furniture would weaken the current hierarchy.
- Use a readable full-size portfolio on phones while retaining the room as the introduction. It can reuse `/desktop/` and the existing content.
- Strengthen project case studies with a few verified outcomes, screenshots and clear statements of your contribution. Several descriptions currently emphasize architecture and capabilities more than evidence of results. Add real measurements only where you have them.
- Keep the brighter Mac against the darker room; repair the exit-state bug instead of globally brightening everything.
- Decide whether the mirror’s cheaper approximation is acceptable. A lower-frequency real reflection is a possible later refinement, but do not restore an expensive per-frame reflection without measuring it.
- Distinguish album-cover-inspired record labels from physical pressing photographs. The newer `tlop-vinyl.jpg` and `yeezus-vinyl.jpg`, for example, use circularly treated cover images; they are not evidence of photographed physical LP labels. The credits still describe parts of the earlier artwork pipeline.
- Update the dated README, album guide and validation notes after the next implementation pass: they still describe the earlier 31-track library, some old furniture positions and prior materials. The current source and this review are more accurate for the new state.
- Watch the playlist size ceiling: the loader silently rejects more than 128 tracks. The present library is 114, so adding 15 more without adjusting that guard would make music disappear. Surface a useful load error when that boundary is exceeded.
